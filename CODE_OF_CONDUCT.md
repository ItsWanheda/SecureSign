# Code of Conduct

## SecureSign Community Code of Conduct

The SecureSign project is committed to providing a respectful, constructive, and inclusive environment for everyone who contributes to or interacts with the project.

This Code of Conduct applies to project contributors, maintainers, reviewers, issue participants, and other community members participating through project-controlled spaces.

---

## Our Standards

We expect participants to:

* Be respectful
* Communicate clearly
* Assume good intent while remaining open to correction
* Give constructive feedback
* Focus criticism on code and ideas rather than people
* Respect different levels of experience
* Welcome useful questions
* Keep technical discussions professional
* Respect privacy
* Follow the project's security reporting process

---

## Constructive Technical Discussion

Technical disagreement is normal and encouraged when handled professionally.

Good disagreement looks like:

> "I think this approach creates unnecessary complexity because..."

or:

> "Could we consider this alternative because it reduces..."

Avoid turning technical disagreement into personal attacks.

---

## Expected Behavior

Participants should:

* Help newcomers understand the project
* Explain reasoning when practical
* Provide actionable feedback
* Respect maintainers and contributors
* Keep discussions relevant
* Avoid unnecessary hostility
* Credit others for their work
* Respect intellectual property
* Report security vulnerabilities responsibly

---

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment
* Threats
* Personal attacks
* Hate speech
* Discrimination
* Sexual harassment
* Deliberate intimidation
* Doxxing
* Publishing private information
* Persistent unwanted contact
* Trolling intended to disrupt collaboration
* Deliberately derailing technical discussions
* Maliciously impersonating another contributor

---

## Security Discussions

Security issues require additional care.

Do not publicly post:

* Passwords
* API keys
* Private keys
* Authentication tokens
* Database credentials
* Personal information
* Exploit details for an actively vulnerable production system

Follow `SECURITY.md` when reporting security vulnerabilities.

---

## Code Review Etiquette

Code reviews should focus on improving the project.

Reviewers should:

* Explain concerns clearly
* Distinguish required changes from suggestions
* Avoid personal language
* Recognize good work
* Ask questions when intent is unclear

Contributors should:

* Respond professionally
* Consider feedback
* Explain disagreements respectfully
* Avoid taking technical criticism personally

---

## Maintainer Responsibilities

Maintainers are responsible for:

* Applying this Code of Conduct consistently
* Keeping discussions constructive
* Addressing unacceptable behavior
* Protecting contributors from harassment
* Handling reports appropriately
* Taking security concerns seriously

Maintainers may remove comments, close discussions, reject contributions, or restrict participation when necessary to protect the project community.

---

## Reporting Problems

If you experience or witness behavior that violates this Code of Conduct, contact the project maintainer privately.

When reporting an incident, provide:

* What happened
* When it happened
* Where it happened
* Who was involved
* Relevant links or screenshots
* Any additional context that may help

Do not publicly expose private information while reporting an incident.

---

## Security Reports

Security vulnerabilities should be reported according to `SECURITY.md`.

Do not use ordinary public issues for sensitive security vulnerabilities.

---

## Enforcement

Reports will be reviewed as fairly and confidentially as reasonably possible.

Depending on the situation, possible actions include:

1. Informal warning
2. Request to correct behavior
3. Removal of inappropriate content
4. Temporary restriction
5. Permanent removal from project spaces

The response will depend on the severity and circumstances of the violation.

---

## Scope

This Code of Conduct applies to project-controlled spaces, including:

* GitHub issues
* Pull requests
* Discussions
* Code reviews
* Project documentation
* Other official communication channels

It may also apply to behavior outside project spaces when that behavior directly affects the safety or participation of the project community.

---

## Good-Faith Participation

Mistakes happen.

A contributor who unintentionally violates a guideline and responds constructively to feedback should be treated differently from someone who repeatedly or deliberately violates the rules.

The goal is to maintain a healthy technical community, not to punish honest mistakes.

---

## Final Principle

The standard is simple:

> **Build good software. Treat people with respect. Report security issues responsibly.**

Thank you for helping make SecureSign a better project.
